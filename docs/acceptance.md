# Приемка Timdoc

## Зафиксированный эталон

Пользователь дважды кликает локальное Windows-приложение, выбирает PDF-акт,
проверяет найденные данные и получает три отдельных DOCX на каждую единицу техники.
Справочник хозяйств и настройки переживают перезапуск. Исходные шаблоны остаются
байт-в-байт неизменными. Сетевые запросы приложению не нужны.

Для акта из `doc_templates` ожидаются:

- хозяйство `ООО «Рощинский»`;
- дата `2026-09-07`;
- модель `RSM SS-780-13`;
- шесть заводских номеров;
- 18 DOCX и один ZIP;
- предупреждение о необходимости заполнить ИНН, которого нет в акте.

## Соответствие заполненным образцам

Эталон: файлы `... МТК ...` в `doc_templates`, заполненные знакомым вручную. Автоматическая
проверка на реальных шаблонах и настоящем Word: `uv run pytest -m eval --no-cov`
(`services/document-generator/evals/test_real_templates_eval.py`, пропускается без
шаблонов или Word). Она проверяет, что фразы форм сохранены, значения стоят на линиях,
сторона потребителя не тронута, Word открывает документы без восстановления и каждый
из них помещается на одну страницу.

## Критерии отказа

- PDF без текстового слоя принят без сообщения об ошибке;
- создано не три документа на позицию;
- заводские номера смешались между папками;
- в DOCX остались `{{ ... }}`;
- прежний комплект перезаписан;
- исходный шаблон изменился;
- пустой или неверный ИНН принят генератором;
- в Форме 4 или 11 исчез текст фразы перед значением или линия стороны потребителя;
- Word открывает документ с восстановлением содержимого;
- талон или форма перестали помещаться на одну страницу;
- линия с подставленным значением стала короче или длиннее исходной, блок подписей
  переехал;
- две копии талона разной высоты;
- заполнены поля для ручного ввода: дата составления, контактное лицо, дата постановки
  на гарантийный учёт.
